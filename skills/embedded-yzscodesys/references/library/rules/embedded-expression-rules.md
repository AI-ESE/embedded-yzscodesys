# 嵌入式框架表达式规则

[返回框架总规则](../embedded-framework-rules.md)。本细则维护求值和副作用顺序；宏参数及展开约束见[宏与常量规则](embedded-macro-rules.md)。

日期：2026-10-23。依据用户提供内容提炼。目标是让求值顺序、条件和副作用可以直接读懂；本次只更新规范。

## 规则

| 编号 | 规则 | 执行方式 |
| --- | --- | --- |
| E01 | 结果不依赖未规定的求值次序 | 在标准允许的求值顺序下均应得到相同预期结果；有先后要求的操作拆为明确语句 |
| E02 | 函数调用不作为另一个函数的实参 | 先将结果保存到有含义的局部变量，再检查和传入下一函数；不把多个有副作用的调用挤在一条表达式里 |
| E03 | 赋值不嵌入条件或调用实参 | if/while等条件只判断，赋值独立成句；不把++/--或赋值混进实参/复杂计算 |
| E04 | 括号体现设计顺序 | 位运算、逻辑、比较、移位等组合的关键分组显式加括号；不为堆括号降低可读性 |

E03不禁止for语法中独立的初始化和循环更新部分；更新仍应简洁且副作用明确。不能把“避免条件内赋值”扩大成禁止正常循环语法。

## 拆分表达式时保持行为

- 保持&&、||和条件表达式原本的短路分支，不能把原先受条件保护的硬件读取、指针解引用或函数调用无条件提前执行。
- 值应在实际需要的分支中取得；错误返回先处理，再进行依赖该值的操作。正常零值和错误状态按接口区分。
- 函数开头集中声明，首次使用前就近赋值；不为遵守声明布局提前读取可能尚无效的数据。
- 拆分不改变单位、有符号性、中间值范围、运算精度及饱和/限幅顺序。宏、强制转换和多次类型提升一并检查。
- 不把volatile字段或GPIO寄存器在同一表达式中的两次访问当作同一个快照；硬件顺序通过HDL契约表达，不在APP/FML直接读寄存器。
- 明确语句顺序仍不保证多字共享数据原子性；需要一致快照或临界区时按所有权规则处理。

## 控制快路径

控制ISR中拆分表达式可以使用局部中间量，但不能借机加入日志、额外硬件读取或新的包装调用。修改后比较目标产物和必要的时序；不因源码看起来更短就宣称更快，也不能仅因源码多一条赋值就认定性能下降。

## 后续检查

重点检查嵌套实参调用、条件内赋值、同表达式的多次更新、短路保护和目标整数宽度。用真实正常/失败路径验证行为，不能只靠格式匹配判定表达式安全。
