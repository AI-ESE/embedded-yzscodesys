# 嵌入式框架宏与常量规则

[返回框架总规则](../embedded-framework-rules.md)。本细则维护宏展开、常量及配置归属；操作顺序见[表达式规则](embedded-expression-rules.md)。

日期：2026-10-23。依据用户提供内容提炼，衔接配置集中、头文件私有性及中断约束。以下为后续整理要求，未据此修改现有源码。

## 规则

| 编号 | 规则 | 执行方式 |
| --- | --- | --- |
| M01 | 表达式宏的括号完整 | 参与运算的每个形参加括号，整个结果表达式也加括号；不只保护局部子表达式 |
| M02 | 多语句宏作为单一语句使用 | 用do { ... } while (0)包裹，调用处加分号；不能只用裸大括号破坏if/else配对 |
| M03 | 宏实参不得含可变副作用 | 不传++、--、赋值或会改变共享状态/硬件状态的调用；输入参数不得被宏意外修改或重复求值 |
| M04 | 有意义数值使用明确名称 | 配置、单位、边界、状态和协议值说明含义；广泛使用的数值只有一个维护来源 |
| M05 | 普通操作优先函数 | 需要类型检查、调试或隐藏实现时使用函数；不为减少源码行数改成宏 |
| M06 | 普通只读值优先有类型const | 模块私有对象在.c定义；共享只读对象也在唯一.c定义，确需公开才在所属.h声明 |
| M07 | 不隐藏改变调用者流程 | 宏避免return/goto/continue/break；必要例外写明实际退出范围和资源清理，不能让调用者误判控制流 |
| M08 | 续行和字符串化含义明确 | 续行反斜杠后不加空格/注释；使用#、##时核对实际展开，不借预处理技巧隐藏硬件访问或向上调用 |

宏格式也遵守 [排版规则](embedded-format-rules.md)。宏/常量名称要自解释，具体历史宏的统一命名仍按后续迁移计划处理，不因本文件批量改SDK宏。

## 函数、宏和const如何选择

- 产品/板级/功能开关按现有统一配置入口维护，不能为了“优先const”把#if条件改成运行时变量。
- C90目标的case标签、枚举、位域宽度及需要整数常量表达式的数组等场合，不能假设const对象可代替宏/枚举。按目标编译器和存储类别选择合法形式，不引入依赖VLA的写法。
- 公共接口常量、固定协议定义和模块私有常量按所属层保留；私有常量不因名称全大写就搬进公共头。配置不等于线上格式。
- 头文件不定义静态const表来规避对象归属；需要查表时表在所属.c维护，检查MAP中的存储位置和占用。const不自动保证对象位于Flash或不占RAM。
- 目标SDK固有宏保持原名。对控制快路径，允许经说明和验证的快宏/inline例外，不强行增加普通函数跳转；普通业务函数不因此全部改成宏。

## 实参、副作用和数值含义

即使当前接口是普通函数，也不在实参中执行++、--或赋值，避免调用关系、参数求值或将来宏兼容实现引入隐患。需要计算的值先在明确顺序下准备，再传入接口，详见 [表达式规则](embedded-expression-rules.md)。

有意修改输出对象或写硬件的接口必须明确输入/输出与副作用；“不允许参数发生变化”不应被误解为所有设置接口都不能修改目标对象。禁止的是不透明的实参副作用及对输入的意外改动。

局部唯一数值可通过相邻注释说明，或使用有含义的局部const/枚举。广泛使用的数值必须命名并统一维护。无歧义的默认零值不额外造宏；硬件/协议中的0若有特殊含义，仍说明其语义。名称或注释写清V/A/ms、寄存器计数、Q格式以及word/octet，不能只把字面量换成模糊名字。

## 后续验证

修改宏时检查调用处、副作用、if/else组合、整数提升和中间值溢出；宏展开不是参数范围校验。格式安全也不能自动消除重复求值。

配置/const迁移比较原值、相关组合的预处理、目标构建和MAP；快路径另外比较实际调用、分支及代码位置。既有检查器扫描部分宏边界，但没有验证本文件全部语义。
