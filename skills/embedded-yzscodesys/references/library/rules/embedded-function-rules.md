# 嵌入式框架函数规则

[返回框架总规则](../embedded-framework-rules.md)。本细则维护函数职责、参数检查、返回结果及并发契约；名称形式见[命名规则](embedded-naming-rules.md)。

日期：2026-10-23。依据用户提供的函数规范提炼，并衔接命名、接口契约及控制中断要求。只记录要求，未据此修改固件行为或宣称全工程已经合规。

## 规则

| 编号 | 要求 | 执行方式 |
| --- | --- | --- |
| F01 | 一个函数围绕一个明确职责 | 名称表达动作；状态机推进可以包含相关分支，不混入弱相关任务 |
| F02 | 处理同一知识的重复代码 | 出现2处即评估提炼；超过3处立即安排消除重复；相似但职责不同的逻辑不强行合并 |
| F03 | 新增函数控制嵌套不超过4层 | 优先早返回、明确状态转换或职责分解；函数外层花括号和单纯作用域不当控制嵌套 |
| F04 | 新增函数形参不超过5个 | 参数相关时用有语义、定长且生命周期明确的请求/上下文；不要把无关参数塞进万能结构 |
| F05 | 可重入性明确 | 优先调用者独立上下文；共享可写全局或static对象必须有同步规则，不以注释代替保护 |
| F06 | 参数检查责任统一 | 缺省调用者负责；公共.h写明检查方、前置条件及非法输入处理；跨外部输入边界另按下文划分 |
| F07 | 完整处理错误和异步结果 | 按每个接口定义处理成功/忙/处理中/失败/超时，不把返回值0/1/2当全工程统一含义 |
| F08 | 及时清理确认废弃的代码 | 查全构建组合、向量、回调、链接及外部入口后删除；未启用不等于废弃 |
| F09 | 不修改的输入优先用const | 指针只读对象使用const限定；顶层值参数const不替代接口契约，不随意强转去掉const/volatile |
| F10 | 隔离隐藏状态和I/O副作用 | 算法尽量显式输入输出；必要状态集中归属；GPIO/Flash等操作在HDL及明确端口，不要求硬件函数变成纯函数 |
| F11 | 检查非参数输入 | 全局快照、存储内容、通信数据等须确认已初始化、有效、范围及所需新鲜度；写明检查所有者 |
| F12 | 除打印/日志类外不用可变参数 | 日志检查格式与参数匹配；不在控制ISR做格式化输出；SDK原有契约不擅自改写 |
| F13 | 文件内函数使用static | 声明和定义均留在所属.c；外部API、SDK回调、向量及链接入口先核对调用契约 |
| F14 | 逻辑与文件组织一致 | 函数处于正确Task/APP/FML/HDL及所属模块；遵守命名表、同名接口头和声明布局规则 |

上述数量约束用于新增及实质重构的自有函数。既有超限项应列出真实用途和迁移安排；SDK/固定回调先登记契约，不为凑数增加空包装。

## 参数与非参数输入的检查责任

1. 缺省由调用者保证内部接口的有效指针、范围、数量、状态和调用顺序，公共.h明确其前置条件。不能调用者、被调用者双方都默认对方已检查。
2. CAN/SPI/串口帧、外部存储或上位机数据属于外部输入。接收/解析边界负责验证其长度、地址、完整性及协议字段；APP业务边界负责产品范围和状态许可。两者检查的约束不同，不视为无意义重复。
3. 对上层直接提供防御性校验的公共接口，可以在.h明确由被调用者检查；调用者处理错误即可，不再拷贝一套相同验证。
4. 数据已验证后，内部处理函数按前置条件使用，不在每层重复相同检查。若所有者、数值或生命周期发生变化，需重新判断约束。
5. 快路径参数可由启动/前台准备并验证；ISR仍保留实际必须的运行时保护，不能为效率删除必要保护，也不为了统一加一层验证调用。

非参数输入同样遵循“谁负责、何时验证”的契约。CRC通过不代表参数范围或设备状态一定允许执行；共享对象非NULL也不代表数据已就绪。

## 重复提炼和实时性

优先提炼前台同一业务决策，减少多个版本各自修改。控制中断内的相似表达式或硬件顺序不得直接套用普通函数提炼：先确认边界，必要时使用经验证的inline/快端口，或登记保留理由。

验收比较目标产物中的直接/间接调用、分支及代码放置；调用点数量和静态代码一致性不能代替实机WCET/抖动测试。不通过更改SDK名来满足自有函数命名。

工程已有重复度检查工具时可记录趋势并纳入现有CI；没有CI时不为执行该规范另建平台，先对实际修改范围做可重复检查。

## 共享状态与同步

- 使用不同上下文实例的同一函数可以重入；同一上下文是否允许并发另行规定。只读共享数据与共享可写数据分别判断，不一律加锁。
- 必要的任务/ISR共享写入根据目标芯片的原子宽度和访问顺序处理；volatile不等于互斥或原子性。
- 临界区保持有界，保存并恢复先前中断状态；不能无条件开中断。ISR不使用阻塞互斥、等待或文件/显示I/O。
- 函数因设计为单实例、状态机或硬件端口而不可重入时，应明确说明并由组合层保证串行调用，不能虚称可重入。

## 返回结果与副作用

调用者在返回时按契约处理错误；异步“已接收/排队”继续跟踪完成或失败。忙时保留还是拒绝请求、重试次数、超时计时及重复副作用必须明确。

确实由统一诊断状态承接错误的接口，须交代查询入口和恢复责任，不能仅将返回值强转void后忽略。失败路径及时释放本机占用资源并保留可恢复状态；本地接受、驱动发送完成、从机确认和持久化完成分别报告。

## 参数、局部变量和注释

参数按2026-10-27用户补充采用Pascal与下划线组合，例如Input_Vol、Dat_Buf、Sample_Count，并使用Vol/Buf/Dat指定缩写。结构体类型/成员/对象执行相同组合形式，普通自动局部变量继续大驼峰，静态变量按数据规则保留S_前缀。变量集中在函数开头声明，在首次读取前就近赋值；若多分支分别初始化，要覆盖每个实际读取路径。

基础整型形参默认使用`u32/u16/u8`、`s32/s16/s8`类型别名；例如`void FML_Chg_Set(u16 Tag_Vol, const u8 *Dat_Buf, u16 Dat_Len);`。这里的类型别名和参数名分开遵守规则，具体位宽必须由目标工具链支持；不能为了统一别名改变SDK原型或协议宽度。

公开.h中的函数注释写明输入/输出、数量、范围、单位、指针持有期、每个返回状态、是否阻塞、是否允许ISR/重入、初始化顺序及确认层级。实现说明算法或特殊时序，不重复无意义模板。

详细说明及真实作者/版本字段见 [注释规则](embedded-comment-rules.md)；函数内表达式与排版分别遵守 [表达式规则](embedded-expression-rules.md) 和 [格式规则](embedded-format-rules.md)。宏/函数选择见 [宏与常量规则](embedded-macro-rules.md)，仍保留快路径例外约束。

## 后续检查

新增或实质修改函数检查嵌套、形参数量、static范围、参数检查责任、返回值处理及异常恢复。回归应覆盖真实正常/边界/失败行为；既有检查器目前不覆盖本文件全部规则，需后续逐项扩充，不能沿用“零违规”推断已全部满足。
