# 公共类型、位域与位操作配置规则

日期：2026-10-27。用户要求C/C++工程有专门的公共类型/宏定义配置文件，并默认采用以下六个基础整型别名。

[返回总规则](../embedded-framework-rules.md) · [结构体与位域](embedded-struct-rules.md) · [命名](embedded-naming-rules.md) · [宏与常量](embedded-macro-rules.md)

```c
typedef uint32_t u32;
typedef uint16_t u16;
typedef uint8_t  u8;
typedef int32_t  s32;
typedef int16_t  s16;
typedef int8_t   s8;
```

这是默认的基础整型类型命名，参数和结构成员的语义名称仍遵守Pascal与下划线组合。例如`u16 Tag_Vol`、`const u8 *Dat_Buf`、`struct Chg_Sta`中的`u16 Output_Vol`。仅当目标确有对应精确位宽时提供别名；浮点、枚举、指针及标准库/SDK固定类型按实际契约使用。

## 规则

| 编号 | 要求 | 适用与验证 |
| --- | --- | --- |
| T01 | 基础类型与常用位操作集中在专门公共配置头 | 建议Common/Inc/Pj_MacroCfg.h；按工程类型头依赖顺序接入，不包含产品对象或机型参数 |
| T02 | 六个默认别名映射精确宽度stdint类型 | 核对stdint可用性、CHAR_BIT、ABI；无uint8_t时明确u8/s8及8位视图不可用，不以unsigned char冒充固定8位 |
| T03 | 兼容别名单点定义并核对冲突 | 用户原片段中的Uint32/Uint16/Uint8、INT8U/INT16U/INT32U/INT16S只在确有兼容需求时接入，INT32U映射u32，不假定unsigned int始终32位 |
| T04 | 位操作使用无符号掩码、有效位号并控制求值次数 | set_bit/clr_bit/get_bit兼容名保留，明确可写无符号左值及位号前提；检查bit31、越界、宏实参副作用与if/else使用 |
| T05 | 有符号视图使用对应有符号类型 | 原8位联合体S8成员应为s8；不可借无符号字段名暗示有符号语义 |
| T06 | 位域与联合体布局视图按目标显式启用 | 新类型和成员执行Pascal_Underscore；核对sizeof、位分配、端序及编译器扩展；不沿用_8_bits等保留标识符样式 |
| T07 | C/C++区别验证联合体与别名规则 | C++不依赖读取非活动联合体成员实现通用重解释；字节序、拆装字节和通信持久化用显式整数运算/编码，布局视图只作已验证ABI的局部用途 |
| T08 | 公共头接入需要独立编译与平台适配证据 | 分别核对C/C++、目标语言版本、SDK重定义、尺寸、移位和volatile/共享读改写；标明模板static/inline助手的头文件例外范围，不扩大普通业务头实现 |

## 文件与接口归属

配套Skill提供`assets/headers/Pj_MacroCfg.h`，按需启用`Pj_BitLayout.h`中的8/16/32位位域/联合体视图。先根据芯片和工具链适配，再复制到具体工程Common/Inc；不是复制模板就完成所有平台验证。

`u32/u16/u8/s32/s16/s8`、必要兼容别名及用户指定小写宏是此基础契约的明确命名例外。模块新参数、结构标签/类型/成员仍执行Pascal_Underscore，不能据此把全部新类型或结构成员改回无语义的小写名称。

公共头中的局部static/inline位操作助手用于单次求值和边界处理，是本模板的限定实现方式。目标编译器不支持时改为其已核实形式，或将普通实现移入对应源文件；记录代码大小和调用影响。SDK已有同名typedef时先确定唯一来源或配置兼容开关，不能用宏覆盖类型声明。

## 布局与并发边界

位操作不天然原子；volatile不代替互斥。硬件寄存器的写1清零、只写、保留位或读副作用必须按规格书及SDK处理，不能直接套普通内存的读改写宏。常用宏不能隐藏系统级失败或同步责任。

位域顺序与字节视图不是跨平台的线格式。结构体sizeof、padding和联合体视图都按实际目标验证；目标没有精确8位类型时，上层协议用明确octet语义适配，不改变协议字段值和长度单位。

模板测试证明宿主C/C++上的列明行为，不能替代CCS、Keil或ESP工具链的目标构建和板级验证。
