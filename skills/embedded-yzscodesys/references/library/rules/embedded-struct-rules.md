# 嵌入式结构体、参数与位域规则

日期：2026-10-27。依据用户新增结构体要求整理；存储期、初始化和对齐解释按C语言及目标工具链落实。

## 规则

| 编号 | 要求 | 边界与核对方式 |
| --- | --- | --- |
| ST01 | 结构体定义和对象声明以分号结束 | `struct Sample_Dat { ... };`定义结构类型；`struct Sample_Dat Sample_Dat;`声明/定义对象；前向声明不提供完整布局 |
| ST02 | 结构体标签、typedef名、对象语义名称和成员均用Pascal与下划线结合 | 如Sample_Dat、Input_Vol、Ready_Flg；必要S_/G_前缀保留，SDK和外部契约原名保留 |
| ST03 | 变量存储位置按声明位置、存储期及链接配置判断 | 自动局部对象通常由ABI安排栈/寄存器，文件级或static对象有静态存储期；结构类型本身不因此占“全局区” |
| ST04 | 读取前完成有效初始化 | 有初始化器时省略成员按语言规则初始化；静态存储期未显式初始化的成员按语言规则初始化；未初始化的自动局部结构体不能当作全零 |
| ST05 | 布局按实际ABI、类型对齐要求和编译选项核对 | 成员声明次序保持，可能有成员间和尾部padding；不能把最大成员的sizeof或CPU字节数当成通用对齐公式 |
| ST06 | pack只在确有外部契约时局部使用并验证 | 核对编译器语法和支持值，支持push/pop时成对恢复；验证非对齐访问、性能和布局，不统一假设所有工具链支持同一pragma |
| ST07 | 结构体参数通常采用有明确生命周期的指针 | 只读输入用const指针；输出/上下文说明修改权、空指针责任、持有期和并发；小对象按值传递需说明接口语义与目标开销 |
| ST08 | 同类型对象可整体赋值，语义相等逐成员比较 | C不支持结构体整体==/!=；memcmp会受到padding、对象表示和非语义字节影响，不能作为通用结构相等判断 |
| ST09 | 普通软件标志位优先用位域与有语义的宏表达 | 位宽、底层类型和宏值明确；实测目标sizeof/对齐后才能宣称节省空间 |
| ST10 | 位域读改写按共享存储单元处理同步 | 相邻位可能共用一次读改写；不同上下文分别写不同位也可能竞争，volatile不保证原子性；禁止取位域地址或依赖offsetof定位位域 |
| ST11 | 通信、Flash/EEPROM和寄存器使用明确契约 | 不直接发送或持久化结构体/位域内存；位顺序、分配单元和端序由实现决定；寄存器沿用经核实SDK/寄存器契约 |
| ST12 | 公开布局与头文件依赖最小化 | 调用者确需完整类型时公开定义，否则可用命名结构的前向声明；头文件仍须自包含，不用少include造成隐藏依赖 |
| ST13 | 模块结构体按所属模块和职责分类命名 | 如Chg_Cfg、Chg_Sta、Chg_Ctx、Chg_Diag；Charge可缩写为Chg，类型、对象和成员执行Pascal与下划线组合，不用无所有者的万能结构 |
| ST14 | 按分类分别管理所有权、生命周期与公开边界 | 配置、状态、上下文、请求/响应、诊断、标志等按实际职责分开；私有类型与对象留模块.c，接口确需类型放所属公共.h；不把所有模块状态堆入一个项目大结构体 |

## 类型、对象与访问

以下为C语言布局示例，具体宽度与类型选用仍须按目标平台确定。函数参数和结构体成员均执行新命名形式。

```c
struct Sample_Dat
{
    u16 Input_Vol;
    u16 Sample_Count;
};

/* 自动局部对象必须显式初始化或在读取前赋值。 */
/* struct Sample_Dat Sample_Dat = { 0U, 0U }; */
/* 对象访问 Sample_Dat.Input_Vol；指针访问 Sample_Ptr->Input_Vol。 */

void FML_Sample_Read(struct Sample_Dat *Sample_Dat);
void FML_Sample_Consume(const struct Sample_Dat *Sample_Dat);
```

`.`用于结构体对象，`->`用于指向结构体的有效指针；指针本身仍须符合空值、生命周期和访问权限契约。同一结构体中的数组成员会随结构体赋值复制，但数组对象本身仍不能直接用赋值运算符整体赋值。

匿名结构可以直接声明对象，例如`struct { unsigned int Ready_Flg; } S_Local_Flags;`。没有命名类型不便跨接口复用；新增公共接口优先采用有明确名称的类型。声明类型不等于建立对象，不把`struct Student`描述成位于某个全局存储区。

部分聚合初始化所省略成员按静态初始化规则处理：算术成员为零值、指针成员为空指针、聚合递归处理。语言零值不保证所有目标的指针/浮点对象表示全为零字节；不以memset替代未经目标验证的语义初始化。C90兼容工程不直接引入未支持的指定初始化、_Alignof或_Static_assert。

## 标志位与宏

```c
#define FML_SAMPLE_FLG_CLR (0U)
#define FML_SAMPLE_FLG_SET (1U)

struct Sample_Flags
{
    unsigned int Ready_Flg : 1;
    unsigned int Fault_Flg : 1;
};
```

宏表达有效值/状态，成员表达含义；不把字段顺序当成位编号。是否节省空间依赖编译器分配单元及对象数量，记录目标sizeof与原方案比较后判断，不承诺两个1位字段在所有芯片上只占一个8位字节。C28x等平台须区分C存储单元与线上octet。

按位域所属存储单元及实际目标指令审查读改写。任务/ISR共享状态优先明确单一写入者；必要时使用适合目标的临界区或快照，保存并恢复中断状态。不能仅因字段不同就认定并发安全。

## 对齐验证和来源

成员按各类型的对齐要求布局，结构体整体对齐与尾部padding依目标ABI确定；成员sizeof与其对齐要求并非通用等式，也不存在一律按CPU字节数封顶的C语言规则。`#pragma pack`是编译器扩展；局部打包可能引入非对齐访问，不能用打包后的内存布局替代显式协议编码。

目标验证记录编译器版本、ABI、选项、sizeof、可适用的offsetof和MAP；使用目标编译器的断言/检查方式。测得偏移和字节数属于该配置，不推广到其他芯片或编译器。

## 模块结构体分类管理

类型名采用“模块语义_职责类别”，必要的实例/通道语义可加入；同一模块的类型、对象、公共接口和文档保持一致。下表分类词为工程适配建议，按实际需求选用，不要求每个模块创建全部结构体或空壳类型。

| 职责类别 | 示例 | 归属与边界 |
| --- | --- | --- |
| 配置 | Chg_Cfg | 参数、阈值、静态选项；区分编译配置与可持久化参数，不混入运行计数 |
| 状态 | Chg_Sta | 当前模式、业务阶段和可查询状态；明确单一写入者 |
| 运行上下文 | Chg_Ctx | 模块内部时序、计数、算法或事务上下文；不聚合其他模块的完整可写对象 |
| 请求/响应 | Comm_Req、Comm_Rsp | 一次命令或事务的数据契约、长度和生命周期；Rsp避免与参考表Res(Resource)混淆 |
| 诊断 | Chg_Diag | 错误、计数、健康和调试快照；不兼作业务控制对象 |
| 标志位 | Chg_Flags | 内聚的软件标志集合，按位域与宏约束处理同步 |
| 业务数据 | Sample_Dat | 有明确用途的采样或计算数据；接口/持久化/协议映射显式定义 |

每个类型登记用途、所有者、初始化/复位、修改入口、读取者、生命周期及并发约束。私有对象如S_Chg_Cfg、S_Chg_Sta分别管理；需要多个实例时通过明确实例上下文传入，不制造无边界的G_Pj_Dat。

确有内聚关系的组合可以包含子结构，但不能通过逐层嵌套把无关模块重新塞回统一大对象。类型过多或成员重复时按职责审查；不按固定成员数机械拆分，也不为减小文件数量合并所有结构体。

依据：[WG14 C11委员会草案N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)的6.2.4、6.5.2.3、6.7.2.1、6.7.9及6.5.16；[GCC结构布局pragma说明](https://gcc.gnu.org/onlinedocs/gcc/Structure-Layout-Pragmas.html)。C11资料用于核对语言事实，实际工程仍遵守已选C版本及目标工具链限制。
