## 资源门槛

设计时同时核对芯片 Flash/RAM 总量、链接可用区域、现有代码/数据占用、保留区与安全余量，区分内部/外部存储及访问限制。预算、目标 MAP/链接报告、运行峰值是三类证据，不互相代替。

- 字库：列实际页面文字/字符集、中文/符号与动态字符范围，记录子集化、字号、字重、字体位深、许可和实际生成大小；检查漏字、动态数值、单位和故障文案。
- 资产：逐项列 Logo、图标、背景、图片、动画的实际尺寸/格式、压缩存储量、解码峰值和缓存；共享资产按实际复用去重，不能把重复副本当共享。
- 驻留：区分逐页专用资产、跨页/弹窗/动画同时驻留集合、预取和缓存上限；全局峰值不能只看每页单独最低值，也不能把互斥页面全部重复相加。
- 显存：按实际颜色格式、行跨度/对齐、单双缓冲、局部刷新/绘制缓冲计算；注明 octet 与目标 C byte 的区别。另算 glyph/image 缓存、对象树、栈/堆、DMA、显示/触摸驱动缓冲和共享任务消耗。
- 落地：用当前目标 MAP核对 Flash/静态 RAM，用可用测量方法取得堆栈/缓存/DMA/解码等峰值；证据注明配置、场景、版本与方法。未测峰值标待测，资源超限不能靠92%视觉评分覆盖。

## 逐页三轮与评分

每轮都比较**该页当前 HTML 与实际程序内容页面**，并涵盖同一组正常/告警/异常/交互状态。可将 U1 侧重内容与布局正向核对、U2 侧重从实际界面反向检查遗漏/交互、U3 侧重修复后整体复核；侧重点不同不等于某轮可省略其他维度。

建议默认权重：布局35、字排20、颜色15、图标/图片10、状态与交互20，总分100；记录各项得分和扣分依据。项目另有约定时先记录权重版本，不在看到结果后调权重凑通过。每页、每轮必须≥92；关键功能、必需文字/单位、告警或关键交互缺失直接不通过，资源约束独立核验。

每轮记录页面/状态ID、HTML版本与 SHA-256、源码/固件版本及摘要、输入与资产摘要、实际截图/交互证据、仿真或实机类别、逐项差异、改动、分项/总分、结果与依据。浏览器自身截图不是目标程序界面证据；仿真可支持对应层级比较，实机未测项保留待测。修复影响已通过项目或共享资源时，更新摘要并重新完成相关轮次；无关证据复用要写明范围。

当前资料生成器只展示审核材料，不自动设计四套 UI、不自动测量相似度、不计算92%评分。执行者按实际证据逐项分析；本文件不宣称任何未知屏幕已设计、编译或通过审核。
