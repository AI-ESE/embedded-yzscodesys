# 嵌入式框架头文件规则

[返回框架总规则](../embedded-framework-rules.md)。本细则维护公开/私有边界及包含关系；接口说明格式见[注释规则](embedded-comment-rules.md)。

日期：2026-10-23。依据用户提供的头文件规范提炼，并与四层架构、SDK原名和中断约束对齐。本文件是后续整理要求，不表示现有工程已全部满足。

## 规则

| 编号 | 要求 | 执行边界 |
| --- | --- | --- |
| H01 | 头文件只公开必要接口 | 放公开函数声明、调用者确需的类型及接口常量；普通实现留在.c |
| H02 | 私有定义留在.c | 文件内函数及其声明、私有宏/枚举/结构、内部状态不放公共头 |
| H03 | 不在头文件定义变量 | 包括普通变量、带初始化的extern、static变量和大型const表；对象在唯一.c定义 |
| H04 | 尽量不以全局变量作为接口 | 优先业务操作、查询或快照API；必须跨文件共享时，唯一.c定义，所属公共.h只作extern声明 |
| H05 | 单一职责和最小依赖 | 头文件只引入声明所需依赖；仅实现需要的include移至.c，不建god.h/Global.h聚合全部业务 |
| H06 | 向稳定接口依赖 | 产品APP依赖稳定FML/HDL契约，底层不反向包含产品头；共享契约要小，不把全部状态搬进Common |
| H07 | 禁止头文件循环包含 | 检查实际.h→.h关系；include guard不能替代消除循环；函数协作图和合并C/H图另行分析 |
| H08 | 自有.c原则上对应同名公共.h | 对外接口在所属.h统一声明；.c优先先包含自己的.h，再包含实现依赖 |
| H09 | 不靠私有头掩盖过大源文件 | 优先按职责拆分模块；不为减少行数把内部实现搬到可任意包含的私有定义头 |
| H10 | 跨文件接口必须通过所属头文件使用 | 不在调用方.c手写extern函数或变量声明；修改接口同步声明、定义及全部调用 |
| H11 | 头文件自包含且可重复包含 | 有唯一include guard；单独包含时类型完整，不依赖调用者先包含其他头的偶然顺序 |
| H12 | 自有include放在extern "C"之外 | C++兼容块只包本模块C接口声明；不要包第三方/标准库头；纯C编译时由__cplusplus保护 |

H04中的extern只是声明，不能带初始化器。公开函数声明可写普通原型，不要求为了“对外”额外增加extern关键字。

## 源文件和头文件的对应关系

- 新增普通自有模块遵守同名.c/.h；确实不提供接口的孤立.c，首先审查它是否应合并或重新划分职责。
- main等入口、SDK/生成文件、向量/链接约定入口按既有契约保留并登记，不为配对生成空头文件或改SDK名字。
- 现有一个模块由多个.c实现、接口归于同一公共头的情况，先核对符号与模块职责，再决定合并或拆分。它属于需要整改或说明的现状，不能直接删除辅助.c。
- 公开类型头、端口头只有在确实承载独立的公共契约时保留；不能把“别人不该include”的私有数据换个文件名继续暴露。

## 和中断、芯片移植规则的衔接

头文件不放普通函数实现是默认规则。控制快路径中确有必要的static inline或宏可以登记例外，注明用途、调用上下文、所属层、共享访问和目标编译器要求；比较实际反汇编、RAM放置与调用变化，不为搬回.c增加中断跳转。

不得在头文件定义可写静态对象来规避全局接口规则：不同翻译单元可能各有一份状态。只读表也不随意复制到头文件。必要的编译期常量按配置/接口常量归属维护。

HDL端口中的SDK名称保持原样；不把SDK依赖扩散到公共业务头。芯片适配过程仍写入相应.h的维护契约，不等于在该头内复制驱动实现。

文件头的版权、版本、作者和修改摘要按 [注释规则](embedded-comment-rules.md) 记录真实事实；宏/只读值的放置及C编译期限制见 [宏与常量规则](embedded-macro-rules.md)。不因补字段伪造历史，不因优先const在公共头定义对象。

## C/C++公共头布局示例

以下只是布局示例，不代表工程新增了同名模块。类型文件采用当前工程已有名称，后续命名迁移另外同步。

```c
#ifndef FML_MOD_H_
#define FML_MOD_H_

#include "Project_Types.h"

#ifdef __cplusplus
extern "C" {
#endif

//========================================================================
// 函数: FML_Mod_Init
// 描述: 示例模块启动初始化；实际模块须补齐真实初始化条件
// 参数: 无
// 返回: 无；本示例不发起从机事务
// 调用: 启动阶段串行调用一次，之后由所属Task安排实际处理入口
// 备注: 前台非阻塞，不允许ISR/重入；不代表工程存在本函数
//========================================================================
void FML_Mod_Init(void);

#ifdef __cplusplus
}
#endif

#endif
```

将include放在extern "C"外是本项目的布局约定，不将“在extern块中包含头”或“嵌套extern块”一概解释成C++语法错误。语言链接与声明一致性可参考 [Microsoft extern文档](https://learn.microsoft.com/en-us/cpp/cpp/extern-cpp?view=msvc-170)。不采纳未经具体编译器版本核实的统一嵌套层数说法。

## 后续检查

- 查看公开声明的真实调用者，将没有外部用途的实现收回.c。
- 单独包含公共头并做重复包含、实际C构建；承诺C++兼容的接口另做C++包含检查。
- 区分.h包含环、源模块协作、快路径例外和必要组合点，避免只凭文件数量下结论。
- 清理include后构建相关功能组合；测量编译时间变化时保留相同工具链和构建条件。
