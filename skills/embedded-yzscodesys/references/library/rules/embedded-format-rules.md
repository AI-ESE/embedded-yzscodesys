# 嵌入式框架排版与格式规则

[返回框架总规则](../embedded-framework-rules.md)。本细则维护缩进、分行和空格；暂定形式与已确认要求分别标明，不据此扩大SDK修改范围。

日期：2026-10-23。依据用户提供内容提炼。适用于新增和后续整理的自有C/H；SDK和直接配套适配代码按平台风格保留。当前仅形成规范，未批量格式化源码。

## 基本布局

| 编号 | 规则 | 执行方式 |
| --- | --- | --- |
| L01 | 每级缩进4个空格 | 新自有代码不混用Tab和空格；续行增加一级缩进，避免靠大量空格远距离对齐 |
| L02 | 逻辑块间留空行 | 变量声明区与执行区、相对独立步骤之间空行；密切相关的声明/函数保持相邻 |
| L03 | 一行一条完整语句 | 不把多个赋值或调用压成一行；for头部的初始化/条件/更新按语法视为一个循环头 |
| L04 | 控制语句与执行体分行 | if/else/for/do/while/switch及case/default各自清楚占行，语句体按层级缩进 |
| L05 | 条件与循环分支成对加花括号 | 新自有if/else各分支及循环体统一加{}，即使只有一条执行语句也如此 |
| L06 | 长语句按逻辑换行 | 优先低优先级操作符处换行，操作符位于续行开头；不按字符数任意切断语义 |
| L07 | 相关代码相邻 | 模块私有定义、辅助函数和业务入口按职责组织，避免把同一操作散到不相关位置 |
| L08 | 注释和语句同样保持层级 | 说明性注释符后一个空格，注释位置见专项规则，不在表达式内部夹注释 |

原文允许多种花括号位置。本工作稿暂定新增自有控制块采用花括号独占下一行、与控制语句同级；这是待继续确认的具体形式，不冒充用户已确认的硬规则，不改SDK样式。已有格式后续按修改模块逐批迁移，不一次重排整个工程。

## 行宽和续行

当前建议以132列作为人工审查参考，不作为已经执行的编译硬门槛。需要更短行宽的编辑器/团队可另定；URL、固定格式表、SDK或机器生成内容按实际登记例外。

长条件或调用按完整子表达式/实参分组换行，增加4空格续行缩进；较低优先级操作符放续行开头。不为凑行宽拆开标识符、字符串语义或宏续行。若格式化造成密集多层条件，应同时检查职责和嵌套深度，而不是只挪空格。

## 空格

- 逗号后一个空格，前面不加空格。分号前不加空格；同一行确有后续语法时分号后留空格，例如for头。
- 双目比较、赋值、算术、逻辑、位运算及移位操作符两侧各一个空格；乘号与指针声明分开判断。
- 单目`!`、`~`、取地址`&`、解引用`*`、自增/自减与其操作数之间不加空格；是否允许自增出现在实参仍按表达式规则约束。
- 成员操作符`->`和`.`两侧不加空格；数组下标和括号内侧不额外加空格。
- if/for/while/switch等关键字与后续左括号之间一个空格；函数名与调用左括号之间不加空格。
- 不为了局部对齐堆叠多个空格。类型与变量之间保留清晰间隔；指针声明示例暂用`uint16_t *Words`，具体形式仍待统一模板确认，不由空格掩盖const/volatile含义。

## 片段示例

下面仅示意排版和语句顺序，不代表新增接口或完整可编译程序；实际函数仍需按专项规则提供契约和开头声明区。

```c
if (Ready != 0U)
{
    Value = FML_Mod_Read();
    Result = FML_Mod_Check(Value);

    if (Result != 0U)
    {
        FML_Mod_Write(Value);
    }
}
else
{
    FML_Mod_Reset();
}
```

do/while的结尾while条件以及多语句宏的包装属于语法结构，格式应可直接辨认，不机械拆坏。声明布局仍按函数开始集中声明、首次读取前赋值执行。

## 格式整理的验证边界

格式整理不改变协议、数据布局、短路行为、SDK符号、关键硬件顺序或中断调用。修改空白/注释时可比较执行token；增加花括号时还要核对else绑定、宏调用和作用域，不能仅用去空白比较证明等价。

只有文档更新时不构建/烧录；实际C/H变更按改动验证，目标构建和必要行为回归不能用旧日志代替。格式化工具若不可用，不为排版任务擅自引入新依赖或格式化SDK。
