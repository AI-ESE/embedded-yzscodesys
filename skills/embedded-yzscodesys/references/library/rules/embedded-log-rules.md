# 工程Log与追加记录规范

日期：2026-10-27。状态：用户明确要求。用于工程构建后的逐次改动追溯及提问复盘检索。

[返回总规则](../embedded-framework-rules.md) · [工程流程](embedded-project-workflow-rules.md) · [记录模板](../templates/embedded-project-log-template.md)

| 编号 | 要求 | 执行方式 |
| --- | --- | --- |
| LG01 | 工程根目录设专用Log文件夹 | 必备Log/版本记录.md和Log/提示词记录.md，名称保持一致；与串口运行日志区别管理 |
| LG02 | 版本记录包含四项固定字段 | 版本号、修改日期、修改涉及文件、修改内容或者功能；文件路径对应本次实际新增/修改/删除范围 |
| LG03 | 提示词记录包含三项固定字段 | 提示词时间、精简提示词内容、最终改善输出；每次提问有摘要和实际处理结论，便于复盘和检索 |
| LG04 | 新记录只在文件末尾追加 | 每条与上一条空行分隔，按发生顺序保存；不倒序插入，不覆盖旧条目，不将多次记录合并抹去历史 |
| LG05 | 记录用于分析后续代码修改 | 改动前检索相关需求/版本记录并对照当前代码，改动后关联文件、行为和结果；未完成/待确认/待测按实际写明，不把计划写成已实现 |
| LG06 | 实施阶段建立并持续维护 | 用户确认方案、开始搭建工程时创建；已有同名记录完整保留。每次有实际改动追加版本，每次提问处理后追加提示词记录；修订更正也追加说明 |

时间使用实际发生时间并说明必要时区，版本号沿用工程版本策略，不替用户强行切换版本体系。历史版本、旧提示词和当前源码不一致时保留差异，按当前证据判断代码如何改动。提示词保存可检索的任务摘要和最终结论，不保存内部推理过程或凭据。

审核前的资料整理仍遵循WF流程；不为创建Log而提前搭建固件工程。方案确认后可补录前期资料阶段已有事实摘要，并标明原提问时间/补录时间，不能伪造过去已写入记录。

使用UTF-8；已有BOM/换行和内容保持原样。单一写入者依次追加，多代理协作由工程维护者汇总后写入，避免并发互相覆盖。Log不是源码摘要、三轮复盘、目标构建或硬件证据的替代品。
