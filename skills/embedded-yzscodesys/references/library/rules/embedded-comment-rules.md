# 嵌入式框架注释规则

[返回框架总规则](../embedded-framework-rules.md)。本细则维护文件头、函数及共享对象说明；代码布局见[排版与格式规则](embedded-format-rules.md)。

日期：2026-10-23。依据用户新增要求，合并此前确认的详细文件头、函数契约、中文UTF-8 BOM及芯片移植说明要求。只补充规范，不表示所有现有注释已经完善。

## 规则

| 编号 | 规则 | 执行方式 |
| --- | --- | --- |
| C01 | 先让代码本身清楚 | 好注释不能代替正确命名和职责划分；重复陈述语句不算有效说明 |
| C02 | 注释准确、明确、无二义性 | 单位、范围、时序、状态和支持限制与当前实现一致，不把待验证写成完成 |
| C03 | 解释意图与约束 | 说明原因、设计取舍、算法依据、硬件时序和特殊限制，避免只翻译代码动作 |
| C04 | 代码和说明同步维护 | 接口、配置、控制分支变化时同步相关.h/.c及说明；删除失效或误导注释 |
| C05 | 自有C/H有完整文件头 | 保留真实版权、版本、作者/维护来源，说明模块内容、用途、依赖、周期、移植点和限制，并记录实际修改摘要 |
| C06 | 声明处说明调用契约 | 输入/输出、数量、范围、单位、指针生命周期、每个返回状态、性能/阻塞、ISR/重入与调用方式 |
| C07 | 定义处说明实现要点 | 解释步骤、算法、选择理由、状态转换和设计约束；与头文件一致，不复制无关模板 |
| C08 | 共享对象详细说明 | 全局和必要静态共享对象写清功能、单位、范围、所有者、初始化、允许读写者及同步要求 |
| C09 | 注释靠近被解释代码 | 放在上方相邻或右侧；上方说明与前一独立代码块空行分隔，缩进与被解释代码一致 |
| C10 | 有意case贯穿必须说明 | 在当前case处理结束、下个case标签之前明确写明继续执行的原因和适用条件 |
| C11 | 同一项目统一语言与样式 | 默认中文说明；SDK标识符/协议名和已标准化缩写保持准确，不自行简写成难懂注释 |
| C12 | 不在表达式中间插注释 | 必要说明置于表达式上方或完整语句右侧；不打断操作符、参数或宏续行 |

代码自解释与详细接口注释同时执行：内部计算不必逐句翻译，公共契约、硬件时序、重要复杂函数及每个自有函数的必要说明仍需保留。

## 文件头内容与真实性

在现有`//========================================================================`文件头样式中补足下列事实：

- 文件名称、模块用途及对外功能摘要；头文件概述提供哪些接口。
- 版权或许可：保留实际项目/供应商声明，不给SDK加上自有版权，不擅自改变源码许可。
- 版本：使用实际模块/固件版本来源；不得虚构已发布版本。
- 作者/维护者：保留已知真实信息。未提供时明确“未提供/待确认”，不把执行工具、登录账号或推测姓名当原作者。
- 依赖与关联文件、初始化顺序、调用周期和上下文。
- 芯片适配内容、SDK对接位置、单位、标度、时序、容量和支持限制。
- 修改摘要：实际日期、真实修改及必要验证记录引用；不补造历史。详细证据可引用对应.md，避免把全部会话历史堆进文件头。

版本、作者等新增字段是维护目标，不表示当前全部文件已经补齐。缺失事实应标明缺失，而不是生成看似完整的记录。

## 函数和数据说明

继续使用用户已确认的`函数/描述/参数/返回/调用/备注`格式。注释明确哪个参数由谁检查；无指针函数不附加“指针借用”模板，void函数不虚构返回状态。

确认层级必须写实：本地RAM接受、排队、FIFO结束、收到从机业务应答、存储真正完成分别说明。非阻塞不等于零耗时；未测量的执行时间标为未测量，不能填写猜测的微秒数。

结构字段和全局对象说明物理单位及无效/未就绪状态；位域若与线上或诊断编码有关，写明位义和兼容边界，不能把C编译器位域布局当作协议保证。

## 废弃说明和临时屏蔽

不长期保留大段注释掉的旧代码。删除前按实际版本管理条件留档：本工程没有Git时先保存原始文件/摘要/备份，不能假设一定能从仓库找回。

临时屏蔽需要留下原因、影响、启用条件及待办引用，不用含糊的“先这样”。由功能宏保留的合法可选模块和SDK契约不当作废弃代码直接删除。

## 注释符和排版

说明性`//`、`/*`与文字间留一个空格，块注释的各说明行统一缩进。既有`//========================================================================`装饰分隔线按用户模板保留，为固定样式例外；不为添加空格破坏当前文件头识别规则。

注释不放在被解释代码下方；跨case说明处于贯穿位置，便于直接看到控制流。其他排版见 [格式规则](embedded-format-rules.md)。

## 后续验收

编码/BOM和注释标记只能自动检查一部分。需要沿真实调用、参数、数据所有权和失败路径人工核对说明，检查作者/版本等事实来源；不能因模板齐全就宣称注释正确。
