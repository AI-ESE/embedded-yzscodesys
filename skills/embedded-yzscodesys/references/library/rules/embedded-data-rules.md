# 嵌入式框架标识符、结构体与变量规则

[返回框架总规则](../embedded-framework-rules.md)。本细则维护对象归属、可见性、初始化及数据格式；完整缩写表只维护在[命名规则](embedded-naming-rules.md)。

日期：2026-10-27。依据用户新增要求提炼；与 [命名和缩写表](embedded-naming-rules.md)、[头文件规则](embedded-header-rules.md)、[函数规则](embedded-function-rules.md)、[结构体与位域规则](embedded-struct-rules.md) 配套。现有源码尚未整体迁移。

## 标识符命名

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| N01 | 名称表达明确业务含义 | 清晰优先于短；避免依赖内部内存路径或模糊的通用名字 |
| N02 | 完整单词或已知缩写 | 不使用汉语拼音；通用/用户确认缩写保持一致；专用缩写先记录解释，不自行生成难懂缩写 |
| N03 | 语义词首字母大写 | 参数及结构体类型/成员/对象用Pascal与下划线结合；普通自动局部变量用大驼峰，静态对象按N06保留S_；层前缀保留APP/FML/HDL及既定Task入口 |
| N04 | 名称不使用无意义数字序号 | 不用Func1/Func2区分职责；通道号、实例号、周期、尺寸、协议编号等真实含义可保留 |
| N05 | 变量以名词或形容词+名词命名 | 函数以动作或动作+对象命名，采用层_模块_功能结构 |
| N06 | 变量存储范围前缀明确 | 确需跨文件可见的全局对象用G_；文件静态或函数静态对象用S_；前缀后保持大驼峰 |
| N07 | 芯片平台/驱动适配保持原体系 | SDK/供应商驱动及直接配套适配代码保留平台风格；新增自有APP/FML接口仍遵守项目规则 |
| N08 | 参数和结构体相关名称采用Pascal_Underscore及指定缩写 | 如Input_Vol、Dat_Buf、struct Sample_Dat及Ready_Flg；Voltage→Vol、Buffer→Buf、Data→Dat优先于完整词默认规则 |

完整词可以超过5个字母，3–5是选择普通缩写时的优先长度，不要求把每个词压短。用户确认的 `State→Sta`、`Project→Pj`、`Module→Mod`、`Voltage→Vol`、`Buffer→Buf`、`Data→Dat` 优先；参考词中的歧义按词表说明处理。协议中的既定缩写不随自有命名改动线格式。

### G_与S_的具体范围

- 模块私有状态优先定义为.c文件内的static对象，例如 `S_FanSta`。
- 确有跨文件共享需要的非static对象才使用 `G_FanSta`，在唯一.c定义；所属公共.h可作extern声明，并写明所有者和读写条件。
- 文件作用域static对象虽然在广义上属于全局作用域，仍使用S_，不叠加G_S_。
- static局部变量也使用S_；static函数仍遵守函数的层/模块/动作命名，不加变量前缀。
- 参数、普通自动局部变量、结构体成员和类型名称不因这条规则添加G_/S_；结构体类型、成员及对象语义部分采用Pascal与下划线组合，例如S_Sample_Dat保留私有前缀。
- SDK/外部ABI/向量/链接契约符号保持原样。G_只是可见性提示，不是允许任意模块读写的授权。

## 结构体和变量

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| V01 | 一个变量只表示一个用途 | 不让同一字段随阶段切换为无关含义；确需变体时用明确状态和对应的数据模型表达 |
| V02 | 一个结构描述一个内聚对象，模块结构体按职责分类管理 | 配置、状态、上下文、请求/响应、诊断、标志等按实际用途分别命名与归属，不建立涵盖所有业务和外设的万能结构；见ST13/ST14 |
| V03 | 尽量少用跨模块全局变量 | 内部数据static私有；外部通过有业务意义的命令/查询/快照接口访问 |
| V04 | 同一共享对象有明确写入所有者 | 创建/初始化/修改集中归属，其余模块只通过契约读取或请求变更，不多方直接修改同一状态 |
| V05 | 不用局部名字遮蔽可见全局/静态对象 | 前缀之外仍应检查实际作用域，不能只靠大小写差异避免混淆 |
| V06 | 通信和存储显式处理格式 | 明确各字段字节序、符号、位宽、缩放和长度单位；不直接传输C结构体/位域/联合体内存 |
| V07 | 所有读取前完成有效初始化 | 函数开头声明，靠近首次使用赋值；覆盖分支路径，区别有效零值与未就绪数据 |
| V08 | 初始化顺序和发布条件明确 | Task组合安排初始化；使用者只在所有者就绪后读取，不依赖跨模块偶然覆盖顺序 |
| V09 | 数据API表达业务语义并处理同步 | 状态修改、模式查询、转速查询分别有清楚含义；禁止只给每个私有字段套getter后继续公开可写对象 |
| V10 | 减少无必要隐式/强制转换 | 转换前检查范围、截断、符号、整数提升、移位和中间运算溢出；转换不能掩盖接口类型错误 |

默认基础整型参数及字段采用用户指定别名`u32/u16/u8`、`s32/s16/s8`，分别对应精确宽度stdint类型；定义集中在[公共类型与宏配置](embedded-type-macro-rules.md)。这六个是类型名，不替代参数的语义名称；例如`u16 Tag_Vol`、`const u8 *Dat_Buf`。标准库、SDK和外部ABI类型保持其契约，缺少精确8位类型时不能把16位类型伪称u8。

## 保留static，不按发布模式取消私有性

用户参考材料中的“调试时STATIC为static、发布时展开为空”未直接纳入规则。发布版取消static会扩大符号可见性、改变封装和链接行为，并可能带来重名或优化变化，与本次模块私有化目标冲突。

普通自有私有变量/函数在调试与发布中均保持static。若确需热补丁或外部工具可见入口，应另行说明补丁ABI、链接要求、资源和验证，不通过全局取消static来实现。这是本次提炼的工程适配建议，后续可针对具体需求讨论。

## 字节序与芯片差异

发送/保存前按具体协议显式编码，接收/加载后显式解码。不是所有协议都用同一种网络字节序；Modbus寄存器字段、CRC字节及其他通信协议分别遵守自己的格式。

特别核对C28x的16位C存储单元、线上8-bit octet、16位参数字及目标平台的实际整数宽度。sizeof、指针跨度、位域顺序不能直接作为跨芯片格式；通信/存储结构的布局和CRC向量在迁移前冻结并验证。

## 所有权与并发

只有一个写入者仍需处理ISR/前台读取一致性，尤其是多字字段和整批快照。根据芯片原子访问能力和时序设计发布/临界区；volatile本身不提供互斥。

普通前台优先使用命令与只读快照。控制中断的紧凑共享控制结构作为明确例外，登记所有者、允许访问的字段及原子性，不为套API增加逐字段函数跳转；后续改动核对目标产物和实际时序。

## 落地与检查边界

新规则先记录，再按模块同步声明、定义、调用、注释和测试。变量改名不改变布局和协议；确需布局调整时另做格式/持久化迁移。

旧工程检查器主要验证旧版参数/局部变量、声明布局、部分分层和注释标记，不自动满足2026-10-27新增命名要求。当前Skill检查需区分参数、结构体和普通变量，并结合人工语义复盘；不能继续沿用旧正则宣称新规范全部通过。规范维护不代表已修改固件或完成目标构建/烧录。
