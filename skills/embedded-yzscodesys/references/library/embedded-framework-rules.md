# 嵌入式程序框架规则

更新日期：2026-10-27。状态：持续打磨的规则工作稿；已确认要求按各条记录执行。适用具体工程时仍需逐项核对。

本文件是框架规则的统一入口，用于整理旧工程、修改接口、增删模块和更换芯片。专项条款放在对应细则中；具体工程的代码状态与验证证据单独记录。配套嵌入式开发Skill按需加载本规则，资料集说明维护安装与调用方式。

## 1. 阅读方式与规则状态

实际工程先按[工程前提、审核与实施流程](rules/embedded-project-workflow-rules.md)收集芯片、规格书、IDE、例程/库、原理图及必要旧代码资料，分析并输出HTML框架与引脚/逻辑/波形审核包，用户确认后再搭建工程。规则阅读先看本文件的分层职责、核心规则和冲突处理，再按工作内容查阅专项细则。缩写表只维护在命名细则中，不在各文档重复复制。

| 状态 | 含义 | 使用方式 |
| --- | --- | --- |
| 已确认要求 | 本会话用户明确提出或接受的要求 | 新增及本次实质修改的自有代码遵守；历史不符合项登记后逐步整改 |
| 工程适配说明 | 将要求落实到嵌入式、编译器及现有工程的解释 | 必须说明技术依据和适用边界；不扩大为用户已确认的通用要求 |
| 暂定约定 | 尚未最终确认的具体形式 | 集中列在第7节，沿用时明确其工作稿状态 |
| 已登记例外 | 固定契约或性能约束下不能机械套用的条款 | 写明对象、原因、替代约束、验证方法；不能作为整模块免审理由 |
| 实施记录 | 某次源码修改及其实际验证结果 | 只证明记录所列范围，不等于全部现行规则已经落实 |

规则冲突先核对用户明确要求和适用范围；具体模块契约应与总规则一致，不能默默覆盖总规则。SDK、入口、中断和固定回调按其契约处理；细则中的默认要求遇到已说明的快路径或工具链限制时，按第6节登记。新的不明确选择提交具体方案审核，不以格式统一为由直接改变行为。

## 2. 架构与职责

总体方向：`Task → APP → FML → HDL`。目录、函数名称、实际调用和数据归属应一致，不能只移动文件而保留原有耦合。

| 层 | 负责内容 | 接口及依赖边界 |
| --- | --- | --- |
| Task：系统任务层 | 启动组织、任务调度、生命周期、功能组合 | 调用已组合的应用入口；不承担产品算法和协议解析；固定任务符号保留 |
| APP：应用层 | 产品流程、业务状态、运行许可、业务范围和策略 | 通过FML契约使用模块能力；同层协作须有明确所有者，不能相互任意改状态 |
| FML：模块接口层 | 可复用算法、协议处理、设备服务及模块接口 | 不绑定产品全局对象；通过明确HDL端口完成硬件操作 |
| HDL：驱动层 | 寄存器、外设、SDK调用、芯片和板级适配 | 保留厂商SDK标识符；不反向依赖产品业务头或包含全部APP状态 |

基础类型、配置与必要共享契约保持小而稳定。下层需要通知上层时，通过明确事件、结果或已约定回调表达，不借聚合头形成反向依赖。启动组合点和控制快路径的必要跨层操作单独说明，不视为普通业务调用的通行方式。

### 模块接口及增删功能

模块应能从其公共`.h`读出用途、依赖、初始化前提、调用周期、调用上下文、状态所有者、资源限制及失败恢复方式。普通前台通过有语义的命令、查询或快照访问数据，避免把内部字段逐个公开。

修改接口时同步声明、定义、全部实际调用点和说明，不保留两套语义不一致的API。增加或删除功能时同时检查任务组合、初始化顺序、配置、资源和失败路径；未启用、不可用和操作失败不能返回假成功。静态任务组合和稳定任务标识按实际系统确定；移植前核对其调度及构建方式。

### 芯片移植说明

相关`.h`写清楚适配步骤和内容：依赖的SDK功能与实际符号、初始化顺序、外设资源、时钟和时序、IRQ/回调连接、数据宽度、单位、限制及验证方法。SDK名称随芯片而异，不为统一框架改名。

新芯片先核对硬件和工具链差异，再实现HDL端口、连接任务及中断入口，最后验证上层接口语义、协议/存储格式和实时性。通用规则不固定GPIO、寄存器、Flash地址、机型电流或厂商函数名；这些属于具体工程资料。

## 4. 命名、数据与接口的共同约束

- 函数按`APP/FML/HDL_模块_动作[对象]`组织；Task沿用其任务入口命名和契约，不盲目改为大写TASK。
- `State → Sta`、`Project → Pj`、`Module → Mod`、`Voltage → Vol`、`Buffer → Buf`、`Data → Dat`为明确指定缩写。指定缩写优先；3–5字母针对其他普通缩写的单个语义词，不强行截断清楚的名称。
- 参数、结构体标签/类型名、对象语义名称及成员（含位域）用Pascal与下划线结合，例如Input_Vol、Dat_Buf、Sample_Dat和Ready_Flg；对象必要的G_/S_前缀照常保留。
- `G_`只提示跨文件可见性，不授权任意模块读写；私有static对象优先使用`S_`。参数、自动局部变量、类型及结构成员不套这两个存储前缀。
- 每个状态有明确创建、初始化和修改所有者；读取者通过约定入口或已说明的快路径访问。`volatile`不等于原子性或互斥。
- 通信和存储显式规定位宽、字节序、符号、标度及长度单位，不直接传输C结构体内存。C28x的16位存储单元与线上8位octet必须区别处理。
- 参数校验缺省由调用者负责，公共.h明确前置条件；外部输入解析边界及APP业务边界各校验其负责的约束。返回错误、异步忙/完成、超时和恢复责任不能遗漏。

## 5. 容易冲突的规则如何一起执行

| 看似冲突的要求 | 统一执行口径 |
| --- | --- |
| 缩写3–5字母与清晰命名 | 清晰优先；允许完整词和用户指定例外，不能制造难懂缩写 |
| 函数开始声明与靠近使用初始化 | 声明集中在开头，赋值靠近实际首次使用，保证每条读取路径已初始化 |
| 头文件不放实现与中断减少跳转 | 普通实现归.c；必要快宏/static inline按第6节说明并验证，不在.h隐藏可写状态 |
| 数据通过API访问与中断时序 | 前台优先语义API；中断共享结构按所有权和原子性约束访问，不机械增加逐字段getter |
| 优先函数与重复代码提炼 | 优先提炼相同职责；控制快路径先验证调用和时序，不能只按相似行数提炼 |
| const优先与编译期常量 | 普通只读对象用有类型const；预处理、case等按目标C编译器的常量表达式要求选择 |
| 默认调用者检查与边界校验 | 明确每项约束的检查者；外部格式校验与业务许可检查职责不同，不重复也不遗漏 |
| 代码自解释与详细注释 | 不逐句翻译代码；每个自有函数仍说明必要契约，公共API及硬件时序必须详细 |
| 自有命名/排版与SDK原样保留 | 自有业务遵守规则；SDK及直接配套适配按平台风格，外部ABI和入口符号不机械改名 |
| 易读表达式与保持原行为 | 拆分不得提前执行原本被短路保护的访问，不改变中间值范围、单位和限幅顺序 |

函数开始声明是当前项目的C90兼容布局要求，不代表已验证全部源码符合严格ISO C90；`//`、inline等扩展以实际工具链支持为准。

## 6. 中断和固定契约例外

控制中断只保留时序必需的采样、保护、控制和状态发布；重处理根据真实实时要求安排到前台。整理代码尽量不增加函数跳转，也不以删除必要保护换取少一次调用。不得借整理增加格式化日志、阻塞等待或不必要的硬件访问。

需要保留快宏、static inline、紧凑共享结构、固定回调或特殊源文件配对时，在所属.h或维护记录写清：适用规则编号、文件/符号、保留原因、调用上下文、所有者及允许访问、同步或时序要求、验证方法和未验证限制。

快路径比较实际直接/间接调用、分支、代码与RAM放置；静态调用计数和反汇编不能代替实机WCET及抖动测试。固定入口及SDK例外只覆盖其契约范围，不豁免周边自有业务设计。

## 8. 具体工程的落实状态

每个工程分别维护现状分析、实施范围、配置归属、审核证据、三轮复盘、实际构建与实测记录。旧报告、模板示例和其他产品的检查结果不能作为当前工程通过依据。

配置入口按当前工程确定；新增命名规则须同步实际源码、调用和检查方法，不因文档更新就宣称全部历史源码已迁移。通用检查只证明其明确覆盖的范围。

## 9. 整理与验收方式

1. 按工程流程收集资料、明确工程范围、工具链、构建组合、现状和未验证项，并完成适用的框架审核。无Git的工程沿用原文件备份、输入摘要及覆盖前核对，不自行初始化Git。
2. 先确定职责、状态所有者、依赖、公共接口及例外，再整理命名、编码、注释和排版。行为修改与格式修改分别说明。
3. 接口和配置修改同步全部相关位置；配置搬迁比较原值、include顺序及相关组合的实际预处理结果，最终由目标编译器验证。
4. 分层检查覆盖实际实现与宏替换体，区分函数式/对象式/续行/字符串化，排除注释及字面量；不把跨宏拼接误识别为真实调用。
5. 按变化采用已有行为回归、预处理/执行token、目标构建及产物比较。仅空白/注释的比较不能证明新控制流或新增花括号一定等价；不为普通改名和说明整理新增只验证源码文字的测试。
6. 公共API人工核对实际调用、校验、所有者和失败恢复；格式或模板齐全不能代替语义正确。源码涉及快路径时按第6节验证。
7. 报告写明实际完成层级：本地接受、排队、驱动发送完成、从机业务确认和持久化完成分别说明；主机测试、目标构建、烧录及实机运行分别记录。
8. 仅修改.md时核对内容、链接、同步及源码未变，不因此进行构建或烧录，也不沿用旧记录宣称新的硬件验证通过。
