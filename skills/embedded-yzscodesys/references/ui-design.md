# UI 设计阶段运行指南

涉及客户 UI 新设计/优化时，加载[UI01–UI17](library/rules/embedded-ui-rules.md)与[UI审核模板](library/templates/embedded-ui-review-template.md)，结合[工程流程](library/rules/embedded-project-workflow-rules.md)、[HTML交付](html-review.md)和[Log规范](library/rules/embedded-log-rules.md)。无 UI 的工程不启用此分支。

工程实际不涉及 UI 时，保持 UI 分支关闭（`architecture.ui.enabled=false`），本组屏幕/驱动、八 Skill 核对/安装、风格 HTML、字库/Logo预算和 U1/U2/U3≥92%均不适用，覆盖矩阵登记具体理由，不因此阻断普通固件流程。通用芯片内存约束与工程 Log 不忽略。

## 开始前

复用已提供的资料，缺项只问实际缺少的部分：屏幕物理/像素尺寸、方向/有效区域、显示驱动芯片、触摸/按键与控制器、接口/颜色格式/刷新约束、当前代码/截图/页面与状态、图形库/SDK、MCU/板卡/链接配置，以及 Flash/RAM 总量/现有占用/预留。上位机或 Web 不直接控制显示驱动时写明适用边界，不能猜芯片。

逐项核对以下八项 Skill：`roughjs`、`shadcn`、`radix-colors`、`github-readme-stats`、`mermaid-diagrams`、`simple-icons`、`fontsource`、`markdown-badges`。逐项读取当前SKILL.md核对实际可用性，已有不重装，缺少再按适用技能安装流程补齐并验证。全部可用后重新审美优化/设计现 UI，不把检查可用性冒充已完成设计。

工具分工：Rough.js 做草图/图形；shadcn用于兼容 Web/审核原型；Radix Colors提供语义配色；Mermaid表达页面/状态/分层；Simple Icons提供真实品牌图标；Fontsource核字体、字形与许可；GitHub Stats/Markdown Badges只用于真实项目文档。MCU字体/图片须转换为现有图形库支持的格式，不能把 React/CSS/WOFF 包直接当固件能力，也不因这些技能更换原技术栈。

## 设计与 HTML 审核

1. 读取现 UI 代码与截图，冻结页面/数据/单位/告警/关键交互和状态基线。默认4套、可3套同内容风格，比较审美和资源取舍，不删除内容凑美观。
2. 设计前统筹**字库、Logo和页面涉及全部资源**：真实字符集/子集、字号/字重/位深/许可；Logo/图标/背景/图片/动画实际压缩存储与解码峰值；共享资源去重、逐页专用资产及同时驻留集合；framebuffer行跨度/对齐/单双缓冲、glyph/image缓存、对象树、栈堆、DMA、驱动缓冲。结合已有代码占用、链接区域和预留估算 Flash/RAM。缺关键值不标预算通过，超限先调整资源/缓冲和视觉方案。
3. 生成独立离线 UI 审核 HTML，按目标像素区说明缩放，提供3–4套页面/状态、缩略/放大、资源表、版本/来源/差异与待确认项；浏览器 DPI 不当作实际屏幕物理尺寸。字体/图标等关键阅读资源不依赖远程请求，遵守许可并安全转义外部文字。
4. 保存用户选择的真实回复、风格/页面范围、HTML版本及摘要，关联 A2/A5；驱动/引脚变化关联相应审核项。HTML 本地选择/意见导出仅是草稿。有效既有确认与授权直接复用，不为每页修正重复索权。

现有 `render_review.py` 生成 A1–A5 **框架审核册**并展示资料；不自动生成3–4套完整 UI、不计算匹配度、不证明92%。独立 UI HTML 由适用设计能力完成，按实际证据人工逐项评分。不要虚构 CLI 参数、自动评分或目标代码生成能力。

## 资料集成与逐页实现

UI 元数据存 `architecture.ui`，沿用当前 profile 能力：`enabled / screen / resources / assets / style_count / selected_style / pages`；驱动资料可随 `screen` 登记，若新增独立 `driver` 字段也按同一结构保存。`architecture` 已被方案摘要覆盖，**仅存方案**：页面ID/标题、选定 HTML/代码位置、屏幕、风格和资源约束；不存持续变化的 U1/U2/U3结果、分数或实际截图。不以空字段表示已满足。

独立风格审核 HTML 和设计资产放资料目录，以 `documents[]` 登记真实 `path / version / sha256`，绑定方案的实际内容。实际三轮记录放 `review.ui_pages[]` 或独立逐页报告；实际截图保存在资料目录 `diagrams` 子目录，以相对 profile 目录路径、类别及摘要关联到各轮证据。持续变化的复盘结果/截图不作为方案 `documents[]` 或方案图形反复改写审批摘要，避免只因补验证记录就要求重新确认。每轮独立保留所比 HTML、源码/固件、输入/资产及截图摘要。方案变更按受影响审核项处理；正常实现、修正和证据整理仍在已有授权范围内，不伪造确认或改摘要以绕过准入校验。

只实现选定风格，按模板页面列表推进。每页 U1/U2/U3 三次独立匹配均核对**当前 HTML 页面与实际程序页面**及正常/异常/交互状态：

- 每轮建议按布局35、字排20、颜色15、图标图片10、状态交互20评分；每页每轮均≥92/100，不能跨轮/跨页平均。权重修改提前约定并记录，不事后凑分。
- 关键功能、必需文字/单位、告警或关键交互缺失直接不通过；Flash/RAM 是独立硬门槛，不能用总分抵消超限。
- 记录 HTML/源码/固件版本摘要、输入/资产摘要、实际截图/交互文件、仿真或实机类别、差异/改动/分项/总分与结果依据；没有实际界面证据不填92%。浏览器原型截图不当作目标程序证据。
- 三轮均符合且资源门槛满足后才切换下一页。修正影响当前页、共享组件、资产或已通过轮次时，更新输入并重核受影响项，不复制三份同一报告。

最终用当前目标 MAP核 Flash/静态 RAM，用实际峰值方法核堆栈/解码/缓存/DMA等；估算与实证分开。按工程流程复核受影响 C1/C2/C3、L1/L2/L3并完成目标编译/优化；编译通过不等于视觉≥92%、实机刷新或资源峰值已验证。未测实机项保留待测。

将选择、差异修正、分数、资源、构建和实际界面证据关联到工程 `Log/版本记录.md`、`Log/提示词记录.md`，按既有 Log 规范追加并在后续修改前检索。当前指南不表示任何未知屏幕已设计或验证。
